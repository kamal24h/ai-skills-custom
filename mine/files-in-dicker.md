برای دسترسی به فایل‌های داخل Docker، بسته به اینکه کانتینر در حال اجرا باشد یا متوقف شده و هدف شما فقط مشاهده باشد یا کپی کردن، راه‌های مختلفی وجود دارد. رایج‌ترین و ساده‌ترین روش‌ها استفاده از `docker exec` و `docker cp` هستند.

### 🐚 ورود به کانتینر در حال اجرا (تعامل مستقیم)

اگر کانتینر در حال اجراست و می‌خواهید مثل یک سیستم لینوکسی معمولی داخل آن بچرخید و فایل‌ها را ببینید یا ویرایش کنید، از `docker exec` استفاده کنید:

```bash
docker exec -it <container_id_or_name> bash
```
یا اگر `bash` در ایمیج نصب نیست (مثل ایمیج‌های Alpine):
```bash
docker exec -it <container_id_or_name> sh
```
با این دستور یک شل تعاملی داخل کانتینر باز می‌شود و می‌توانید با دستوراتی مثل `ls` و `cat` فایل‌ها را ببینید .

### 📋 کپی کردن فایل‌ها بین هاست و کانتینر

اگر فقط می‌خواهید فایلی را از داخل کانتینر بیرون بکشید یا برعکس، `docker cp` بهترین گزینه است. این دستور روی کانتینرهای **در حال اجرا و متوقف‌شده** کار می‌کند .

**کپی از کانتینر به هاست:**
```bash
docker cp <container_id_or_name>:/path/to/file /path/on/host
```

**کپی از هاست به کانتینر:**
```bash
docker cp /path/on/host <container_id_or_name>:/path/in/container
```
همچنین می‌توانید کل یک پوشه را به صورت بازگشتی کپی کنید .

### 💾 اتصال دائمی یک پوشه (Mount)

اگر می‌خواهید فایل‌های خاصی را به طور مداوم بین هاست و کانتینر به اشتراک بگذارید (مثلاً برای توسعه)، هنگام اجرای کانتینر یک دایرکتوری از هاست را به داخل آن Mount کنید:

```bash
docker run -v /path/on/host:/path/in/container <image_name>
```
اینطوری هر تغییری در آن پوشه از داخل کانتینر، مستقیماً روی هاست هم اعمال می‌شود و برعکس .

### 💡 نکته برای فایل‌های سیستمی خاص

دستور `docker cp` نمی‌تواند برخی فایل‌های سیستمی مثل موارد موجود در `/proc`، `/sys` یا `/dev` را کپی کند. برای این موارد می‌توانید از ترکیب `docker exec` و `tar` استفاده کنید تا محتوای مورد نظر را به صورت استریم منتقل کنید .
