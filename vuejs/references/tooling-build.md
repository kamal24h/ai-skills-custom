# Tooling & Build

Vite configuration, type checking, linting, environment variables, and project scaffolding for Vue 3.

## 1. Scaffolding

```bash
pnpm create vue@latest        # official: TS, Router, Pinia, Vitest, Playwright, ESLint
pnpm create nuxt@latest       # SSR / full-stack
```

`create-vue` is the reference setup — match its structure when adding tooling to an existing project.

## 2. Vite Configuration

```ts
// vite.config.ts
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig(({ mode }) => ({
  plugins: [vue()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
    dedupe: ['vue'],                      // critical in monorepos / linked packages
  },
  server: {
    port: 5173,
    proxy: {
      '/api': { target: 'http://localhost:8080', changeOrigin: true },
    },
  },
  build: {
    target: 'baseline-widely-available',
    sourcemap: mode !== 'production',
    rollupOptions: {
      output: {
        manualChunks: { vendor: ['vue', 'vue-router', 'pinia'] },
      },
    },
  },
}))
```

Notes:

- **`resolve.dedupe: ['vue']`** — two Vue copies silently break `provide`/`inject` and cross-boundary reactivity. Essential when linking a local UI package.
- The dev proxy avoids CORS configuration in development; production uses the real origin.
- `manualChunks` is a starting point, not a requirement — measure with a bundle report before hand-tuning.
- JSX/TSX needs `@vitejs/plugin-vue-jsx`.

## 3. Type Checking

```jsonc
// package.json
{
  "scripts": {
    "dev": "vite",
    "build": "run-p type-check build-only",
    "build-only": "vite build",
    "type-check": "vue-tsc --build",
    "lint": "eslint . --fix",
    "format": "prettier --write src/",
    "test:unit": "vitest",
    "test:e2e": "playwright test"
  }
}
```

**`vite build` does not type-check.** `vue-tsc` must run in CI, gating the build.

```jsonc
// tsconfig.json (project references, as generated by create-vue)
{
  "files": [],
  "references": [
    { "path": "./tsconfig.node.json" },   // vite.config.ts, scripts
    { "path": "./tsconfig.app.json" }     // src/**
  ]
}
```

```jsonc
// tsconfig.app.json
{
  "extends": "@vue/tsconfig/tsconfig.dom.json",
  "include": ["env.d.ts", "src/**/*", "src/**/*.vue"],
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  }
}
```

Path aliases must be declared in **both** `tsconfig` (for the type checker) and `vite.config.ts` (for the bundler).

## 4. Environment Variables

```
.env                 # all modes, committed
.env.local           # all modes, gitignored
.env.development     # dev only
.env.production      # prod only
```

```ts
// env.d.ts
/// <reference types="vite/client" />
interface ImportMetaEnv {
  readonly VITE_API_URL: string
  readonly VITE_SENTRY_DSN?: string
}
interface ImportMeta { readonly env: ImportMetaEnv }
```

```ts
// lib/config.ts — the single read point
export const config = {
  apiUrl: import.meta.env.VITE_API_URL,
  isProd: import.meta.env.PROD,
} as const

if (!config.apiUrl) throw new Error('VITE_API_URL is required')
```

Only `VITE_`-prefixed vars reach client code — and everything that reaches client code is **public**, inlined into the bundle. Secrets belong on a server.

## 5. ESLint (Flat Config)

```js
// eslint.config.js
import pluginVue from 'eslint-plugin-vue'
import vueTsConfigs from '@vue/eslint-config-typescript'
import skipFormatting from '@vue/eslint-config-prettier/skip-formatting'

export default [
  { files: ['**/*.{ts,mts,tsx,vue}'] },
  { ignores: ['**/dist/**', '**/coverage/**'] },
  ...pluginVue.configs['flat/recommended'],
  ...vueTsConfigs.recommended,
  skipFormatting,
  {
    rules: {
      'vue/multi-word-component-names': 'error',
      'vue/require-v-for-key': 'error',
      'vue/no-v-html': 'warn',
      'vue/component-name-in-template-casing': ['error', 'PascalCase'],
      'vue/define-macros-order': ['error', {
        order: ['defineOptions', 'defineProps', 'defineEmits', 'defineSlots'],
      }],
      'vue/no-unused-refs': 'error',
      'vue/prefer-true-attribute-shorthand': 'warn',
      '@typescript-eslint/no-explicit-any': 'error',
    },
  },
]
```

High-value `eslint-plugin-vue` rules to keep enabled: `require-v-for-key`, `no-use-v-if-with-v-for`, `no-mutating-props`, `require-explicit-emits`, `multi-word-component-names`, `no-v-html`, `no-side-effects-in-computed-properties`.

Let Prettier own formatting; disable stylistic ESLint rules (`skip-formatting`).

## 6. Editor & Language Server

- **Volar / Vue - Official** extension. Disable Vetur if present.
- Enable **Takeover Mode** (or the current equivalent) so one language server handles both TS and Vue — mixing servers causes duplicated and contradictory diagnostics.
- `vue-tsc` and the editor extension share a version line; keep them in step or diagnostics diverge from CI.

## 7. Auto-Import Plugins

```ts
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'

plugins: [
  vue(),
  AutoImport({ imports: ['vue', 'vue-router', '@vueuse/core'], dts: 'src/auto-imports.d.ts' }),
  Components({ dts: 'src/components.d.ts' }),
]
```

Trade-offs: less import noise, but symbol origins become invisible, generated `.d.ts` files must be committed or regenerated in CI, and "go to definition" degrades in some setups.

**Do not add these to an existing explicit-import codebase without user consent.** Nuxt provides equivalent behavior out of the box.

## 8. Git Hooks

```jsonc
// package.json
{
  "lint-staged": {
    "*.{ts,vue}": ["eslint --fix", "prettier --write"],
    "*.{css,json,md}": ["prettier --write"]
  }
}
```

Run `vue-tsc --noEmit` and unit tests in CI, not in a pre-commit hook — hooks that take 30 seconds get bypassed.

## 9. CI Pipeline

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint
      - run: pnpm type-check
      - run: pnpm test:unit --run
      - run: pnpm build
```

Gate order matters: lint and type-check fail fastest, so run them first.

## 10. Library Mode (Publishing a Vue Package)

```ts
export default defineConfig({
  plugins: [vue(), dts({ tsconfigPath: './tsconfig.app.json' })],
  build: {
    lib: { entry: 'src/index.ts', formats: ['es'], fileName: 'index' },
    rollupOptions: {
      external: ['vue'],                        // never bundle Vue
      output: { globals: { vue: 'Vue' } },
    },
  },
})
```

- `vue` is a **peer dependency**, always externalized.
- Ship types with `vite-plugin-dts`.
- Consider shipping source `.vue` files for design systems so the consuming app compiles them and tree-shaking works.

## Anti-Patterns

| Anti-pattern | Consequence | Fix |
|---|---|---|
| No `vue-tsc` in CI | Template type errors ship | `type-check` gate |
| Alias in Vite but not `tsconfig` | Editor errors, or vice versa | Declare in both |
| Two Vue copies | Broken inject/reactivity | `resolve.dedupe: ['vue']` |
| Secrets in `VITE_*` | Shipped in the bundle | Server-side only |
| Vetur + Volar together | Contradictory diagnostics | Disable Vetur |
| Auto-imports added silently | Opaque symbol origins | Ask first |
| Prettier and ESLint both formatting | Fight on every save | `skip-formatting` |
| Bundling `vue` in a library | Duplicate runtime for consumers | `external: ['vue']` |
| Heavy pre-commit hooks | Developers bypass them | Move to CI |
| Hand-tuned `manualChunks` without data | Worse caching than the default | Measure first |
