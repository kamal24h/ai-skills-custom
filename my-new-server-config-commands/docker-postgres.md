برای انتقال پایگاه داده PostgreSQL از یک کانتینر Docker به کانتینر Docker دیگر در سروری متفاوت، بهترین و قابل اعتمادترین روش استفاده از ابزار رسمی `pg_dump` برای خروجی گرفتن (Dump) و سپس `psql` برای بازیابی (Restore) است. این روش تضمین می‌کند که حتی اگر نسخه‌های PostgreSQL دو طرف کمی متفاوت باشند، داده‌ها به درستی منتقل می‌شوند .

در ادامه مراحل گام‌به‌گام آورده شده است:

### 🔹 گام اول: خروجی گرفتن از پایگاه داده در سرور مبدأ

ابتدا باید از داخل کانتینر PostgreSQL در سرور مبدأ، یک فایل پشتیبان تهیه کنید. فرض بر این است که نام کانتینر شما `postgres_source` و نام پایگاه داده `mydb` است.

```bash
# وارد کردن دستور به کانتینر مبدأ و اجرای pg_dump
docker exec -t postgres_source pg_dump -U postgres -d mydb > mydb_dump.sql
```
*   **نکته:** اگر کاربر شما `postgres` نیست، آن را با `-U` جایگزین کنید. دستور `pg_dump` یک فایل SQL متنی تولید می‌کند که تمام ساختار و داده‌های پایگاه داده را در بر دارد .

### 🔹 گام دوم: انتقال فایل پشتیبان به سرور مقصد

فایل `mydb_dump.sql` را که در سرور مبدأ ایجاد شده، با استفاده از `scp` یا `rsync` به سرور مقصد منتقل کنید.

```bash
# انتقال فایل از سرور مبدأ به سرور مقصد (این دستور را روی سرور مبدأ اجرا کنید)
scp mydb_dump.sql user@destination_server_ip:/path/to/destination/
```

### 🔹 گام سوم: آماده‌سازی و بازیابی در سرور مقصد

در سرور مقصد، ابتدا مطمئن شوید کانتینر PostgreSQL در حال اجراست. سپس پایگاه داده خالی را ایجاد کرده و فایل را وارد کنید.

```bash
# 1. ایجاد پایگاه داده خالی (اگر از قبل وجود ندارد)
docker exec -t postgres_target createdb -U postgres mydb

# 2. بازیابی داده‌ها از فایل SQL به داخل کانتینر مقصد
docker exec -i postgres_target psql -U postgres -d mydb < /path/to/destination/mydb_dump.sql
```
*   **توضیح:** دستور `psql` فایل SQL را می‌خواند و دستورات آن را اجرا می‌کند تا ساختار و داده‌ها بازسازی شوند .

### 💡 نکات مهم و عیب‌یابی

*   **نسخه‌ها:** روش `pg_dump` برای انتقال بین نسخه‌های مختلف PostgreSQL (مثلاً از ۱۴ به ۱۶) بسیار مناسب است، اما همیشه توصیه می‌شود ابتدا در یک محیط تست، سازگاری را بررسی کنید .
*   **مالکیت اشیاء (Ownership):** اگر در پایگاه داده مبدأ کاربر خاصی مالک جداول باشد، ممکن است هنگام بازیابی در مقصد با خطا مواجه شوید. برای جلوگیری از این مشکل، می‌توانید از گزینه `--no-owner` در `pg_dump` استفاده کنید تا مالکیت اشیاء نادیده گرفته شود و کاربر فعلی مقصد مالک همه چیز شود .
*   **حجم داده:** برای پایگاه‌های داده بزرگ (چند صد گیگابایت)، این روش ممکن است زمان‌بر باشد. در چنین مواردی، استفاده از فرمت `-Fc` (فرمت فشرده) به همراه `pg_restore` می‌تواند سریع‌تر و انعطاف‌پذیرتر باشد .

اگر با خطای خاصی مواجه شدید یا حجم داده‌ها بسیار زیاد است، جزئیات بیشتری را به اشتراک بگذارید تا راهنمایی دقیق‌تری ارائه شود.
